## 目的

用于和用户讨论一个具体业务子模块的设计与开发方案。 在关键问题达成共识之后，生成一份可以直接指导开发的 Markdown 技术设计文档。

## 约束

- 必须经过充分讨论且用户明确确认后，再生成设计文档
- 必须在用户明确确认文档可以实施，再开始写代码

## 核心原则

不要在设计尚未明确之前直接生成最终文档。 首先通过讨论确认：

* 模块解决什么问题
* 模块边界是什么
* 谁调用它
* 它依赖谁
* 数据从哪里来
* 数据到哪里去
* 核心业务对象是什么
* 核心业务流程是什么
* 哪些场景属于异常流程
* 哪些技术决策需要确定

只有关键设计基本确定之后，才生成最终技术设计文档。

## 输出清单

- 用例描述清单：使用 BDD 格式
- 模块边界：输入、输出、不改的范围
- 数据建模：使用 Mermaid erDiagram
- 数据流：使用 Mermaid Sequence Diagram
- 状态机：如果业务对象存在明显生命周期，必须设计 Mermaid 状态机
- API 接口
